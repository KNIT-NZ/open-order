# Open Order — P0 privacy cutover

This source release removes the ordinary search route's write to `query_logs`, including query text and unstructured debug metadata. It does not delete, export or modify historical rows or database schemas. No replacement persistent telemetry sink is introduced pending verification of expiry and least-privilege access. Search responses expose a random per-request reference; AI retains its existing in-session diagnostics. A reference alone does not enable exact replay or guarantee an operator-side trace exists.

The search API now accepts POST `/api/search` with a JSON object containing `q`, optional `corpus`, `limit` and `offset`. GET is rejected without processing the search. Search questions are no longer written into the URL by ordinary search state updates. Existing citation/deep links can still contain public authority labels (and previously created URLs may contain questions); initial requests to such URLs can be visible to infrastructure. Search and AI response cache headers prohibit storage by compliant caches. These controls cannot erase prior browser history, infrastructure logs or backups.

AI requests are processed by configured external AI services. Hosting and provider handling, retention, training, active routing and account settings are not established by this code change. Do not submit confidential, privileged or identifying material. Do not post questions or diagnostic snapshots in public issues. The existing GitHub feedback link is for non-sensitive reports; use synthetic reproductions. Open Order is independent and unofficial, not endorsed or operated by Parliament; consult the original authorities and appropriate official guidance.

Production acceptance must verify the exact deployed SHA, synthetic requests, aggregate legacy count stability and vendor settings without retrieving historical content. A privacy-preserving operational event store, enforceable expiry, separate access boundaries, private correction contact and verified corpus-edition disclosures are outstanding. Historical deletion and any production database schema operations require separate approval. Do not restore an earlier content-writing release as routine rollback.
