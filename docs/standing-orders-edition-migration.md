# Edition replacement — Standing Orders 2026

The indexed 2026 candidate is reconciled against Parliament's official Word volume and all eight chapter and six appendix pages. The edition manifest pins the candidate payload and original source checksums. The full reviewed candidate is a separately retained public-source artifact, not an unreviewed runtime download. The database `documents.source_checksum` identifies the exact imported candidate payload; its metadata carries the Word and HTML manifest checksums. The effective date is not asserted to be the publication date.

## Workflow

1. Acquire official sources and compare against the authoritative volume, including numbered clauses, revoked orders, table relationships and source anchors. Retain the exact capture and candidate artifacts. Never import competing versions or silently fill missing text.
2. Review the edition-sensitive citation grammar and source references. The legacy numeric neighbour search remains integer-only: a suffixed order must not be mistaken for its base number. SO 121 still denotes Personal reflections. The app supports existing and new labels before database cutover. Appendix table row labels are internal locators, not official clause numbers.
3. Publish and verify the source compatibility release and exact hosted CI/security results before any database write. The Sources page reads the database's active edition; its 2026 checksum recognition is tied to this reviewed candidate.
4. Use the guarded operator wrapper to invoke the single-client `scripts/replace-standing-orders-corpus.mjs` transaction with a pinned candidate. It locks the corpus tables against concurrent writes, verifies the existing 2023 baseline, saves a complete local backup of the old SO document/sections/chunks (including IDs and build references), inserts the replacement sections and chunks, checks exact row roundtrips, vectors, known witnesses, Speakers' Rulings and zero legacy logs, and commits only if all checks pass. The backup contains public parliamentary material only. Keep it local; do not upload it unless specifically necessary. No schema changes.
5. Verify actual production direct search, citation links, Sources page and synthetic AI questions. Source and database acceptance are distinct. Preserve the backup; restoration requires a separately reviewed reverse transaction using its exact rows and existing build references. Never restore raw query logs, old privacy code or the entire database to roll back this corpus.

The previous chapter-only write importer is retired and metadata seeding skips Standing Orders to prevent a second active edition. Its parser remains available for offline historical comparison. This replacement workflow targets the existing database, not fresh-install bootstrap. Future editions need fresh source reconciliation, updated provenance and an explicit baseline review; do not blindly change the edition label or reuse this 2026 approval. Session-specific orders and later changes need separate currency assurance.
