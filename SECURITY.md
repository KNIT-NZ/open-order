# Security policy — Open Order

## Reporting a vulnerability

Please use the repository's [Security tab](https://github.com/KNIT-NZ/open-order/security) and its private vulnerability reporting feature if available. Do not open a public issue containing exploit details, credentials, private queries, personal information or other sensitive material. If private reporting is not available, open a minimal issue requesting a private contact channel, without describing the vulnerability or attaching sensitive information.

Include, through an agreed private channel, the affected version or commit, a minimal reproducible description, impact and any proposed mitigation. Redact tokens, secrets and personal information. Test only systems for which you have permission; do not test the public service in a way that disrupts it or exposes other users' data.

The maintainers will assess reports, prioritise remediation according to risk and coordinate disclosure where practicable. This policy is not a guarantee of a particular response time or a bug bounty.

## Scope and limitations

The maintained branch is `main`. Report vulnerabilities in the current code or deployed service; third-party dependency issues may also need to be reported upstream. Older commits are not guaranteed security support. Ordinary bugs and documentation corrections may be reported through public issues, without sensitive information.

Open Order handles questions about parliamentary procedure. Queries can contain confidential procedural intentions even where the source corpus is public. Do not include sensitive query contents in public reports. A source or answer error that creates a security or privacy risk should be reported privately; other procedural accuracy concerns can be submitted as corrections with public source references. Do not treat generated answers as authoritative procedural rulings or professional advice.
